One codebase,
three PlaceITs

The website, the installed app, and the Play Store app all run the same code. Some things only happen in the app. This page explains which, and why.

The three versions

Same code, three different places it can be running.

Browser

The website

Someone visits getplaceit.com in Chrome or Safari. It should feel like a normal web page.

App

Installed app

Someone tapped "Install app" in Chrome. It opens from the home screen with no address bar.

App

Store app

The real Android build. Same web pages inside a native wrapper.

What's different in the app

Everything here is on in the app and off on the website — unless the badge says otherwise.

Where to change things

Three files. You'll almost always only need the first one.

  1. src/config/app-features.ts — the switchboard.
    One line per feature. Each is set to app, browser, native, all, or off. Change a line, and the whole app follows. Start here.
  2. src/lib/app-mode.ts — the detector.
    Works out which of the three versions is currently running.
  3. src/app/layout.tsx — the boot script.
    Runs the same check a split second earlier, before anything is drawn on screen. That's why you never see the wrong version flash up first.

Files 2 and 3 do the same job twice on purpose — the boot script has to run before everything else, so it can't share code. If you change one, change the other.

Two things you can't change on their own

Pull-to-refresh & overscroll

Turning off the browser's built-in pull-to-refresh is what makes room for ours. Turn that off without turning ours on and users get no refresh gesture at all. Keep them together.

Splash screen & the hidden page

The page is deliberately hidden for a moment so the splash can cover it cleanly. There's a 4-second safety timer that un-hides it no matter what. Don't remove that timer — it's the only thing between a JavaScript error and a permanently blank screen.

How to test it

  • Fake the app on your laptop: add ?appmode=1 to any URL. It sticks until you close the tab. ?appmode=0 turns it off.
  • Test the real website: a normal tab, no extra bits in the URL.
  • Test the installed app: Chrome menu → Install app → open it from your home screen.
  • Test the store app: cd placeit-mobile && npx cap run android.

Quick check: open developer tools and look at the <html> tag. You should see either is-app-mode or is-browser-mode — never both.

The back button, vibration and keyboard behaviour can't be tested on a laptop at all, even with ?appmode=1. Those need a real phone.

Before you ship

Offline mode saves data onto the phone

To work offline, the app writes whatever you last loaded — your profile, your applications — into the phone's storage as plain text.

It's wiped when you log out, and it expires after 24 hours. But if you add a screen that loads anything more sensitive than that, add it to the DO_NOT_PERSIST list in src/lib/query-persist.ts first.

Set NEXT_PUBLIC_BUILD_ID in your build

Saved data is tagged with the version that saved it. Without this, every release shares the same tag, and a release that changes the shape of your data could make the app crash on old saved data.

Dark mode is the app only, on purpose

The colours flip automatically almost everywhere, but around 57 places in the code have a colour written out by hand, and those won't change. The portal is covered; the public marketing pages aren't.

That's why it's app-only for now. Once someone has walked through the marketing pages, flip darkMode to all in the switchboard.

Not built yet

  • Push notifications. "Your application was viewed", "a new PPA matches your course". The single best reason for someone to keep the app installed. Needs backend work too.
  • App links. Right now, verification and password-reset emails open the browser instead of the app.
  • Camera upload for CVs and documents.
  • Skip the splash when returning from the background — it currently replays every time.
  • The "get the app" banner for website visitors.
